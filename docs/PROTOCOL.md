# Notes: SIDBlaster serial protocol and SIDPLAY/Windows' HardSID use

## SIDBlaster-USB Tic-Tac Edition

Hardware: FT232RL (VID/PID `0403:6001`, product string `SIDBlaster/USB`) feeding a PIC16F886. Firmware 1.1 (`assid8.asm` in the Tic-Tac repo).

- UART: **500000 baud, 8N1, no flow control** (DTR/RTS/CTS aren't wired).
- Every command starts with a header byte:

  | bit | meaning |
  |---|---|
  | 7 | sync, must be 1 (bytes with bit 7 clear are ignored as headers) |
  | 6 | 1 = write, 0 = read |
  | 5 | level driven onto the SID's `/RES` pin (1 = run) |
  | 4–0 | SID register |

- **Write:** `0xE0 | reg`, then the data byte.
- **Read:** `0xA0 | reg`; the PIC answers with one byte.
- **Reset:** a header with bit 5 clear (e.g. `0x80`) holds `/RES` low until the next header. It also triggers a read, so the PIC sends back a byte to discard.
- The device does **no timing**: each write is applied as soon as it arrives. Pacing is entirely the host's job.
- SID Φ2 is 1 MHz, generated by the PIC from its internal 8 MHz oscillator (not a crystal).

With the FTDI VCP driver this is an ordinary COM port, so plain Win32 `CreateFile`/`SetCommState` works; D2XX isn't needed. 500000 baud is 3 MHz ÷ 6, an exact divisor, so even FTDI's 2004 Windows 98 driver sets it correctly.

## SIDPLAY/Windows (win32 version, Nov 7 2002)

The libsidplay1-based player by Michael Schwendt and Adam Lorentzon.

- Loads `HardSID.dll` with `LoadLibraryA` and resolves four functions with `GetProcAddress`. All are `__stdcall`:

  ```c
  BYTE GetHardSIDCount(void);
  void WriteToHardSID(BYTE dev, BYTE reg, BYTE data);
  BYTE ReadFromHardSID(BYTE dev, BYTE reg);
  void MuteHardSID_Line(BOOL mute);
  ```

- The device settings dialog creates the HardSID device (load + `GetHardSIDCount`) and only enables the HardSID option if that succeeds. A DLL that fails to load leaves the option greyed out.
- `GetHardSIDCount()` must be at least `DeviceID + 1`, otherwise it reports "No device found. Run HardSIDConfig.exe".
- Playback start: `MuteHardSID_Line(1)`, writes 0 to `$00`–`$18`, then `MuteHardSID_Line(0)`.
- Pause: `ReadFromHardSID(dev, 0x18)` to save the volume, then writes `$18 = 0`. Resume writes the saved value back (masked to `$0F` when the filter is disabled). On a real SID `$18` is write-only, so the DLL must answer from the values written.
- Register writes come straight from SIDPLAY's 6510 emulation, in real time, with no cycle stamps. Sample (digi) playback is a separate loop writing 4-bit values to `$18`.

## Why the official SIDBlaster DLLs don't load on Windows 9x

The SIDBlaster HardSID-emulation DLLs (including the 2015 build and v518) are linked with subsystem version 6.0 and import functions Windows 98 lacks, such as `EncodePointer`/`DecodePointer`, `GetModuleHandleExW`, `SetFilePointerEx`, SRW locks, and in v518 `GetSystemTimePreciseAsFileTime`. They also bind `FTD2XX.dll` by ordinal from a modern D2XX.
